# 0027. SSO con OpenID Connect

- Fecha: 2026-10-19
- Estado: aceptada
- Afecta: build spec etapa 4 (4.5)

- Authorization code con PKCE (S256, verifier de 64 caracteres) usando `AsyncOAuth2Client` de Authlib; discovery por `issuer_url` (cache de 10 minutos y se exige que el `issuer` del documento coincida); el `id_token` se valida con las llaves JWKS del proveedor (joserfc, de los autores de Authlib): firma, `iss`, `aud`, `exp` y `nonce`.
- El estado del intento (state, nonce, verifier, proveedor y a dónde volver) va en una cookie firmada con HMAC, `HttpOnly`, `SameSite=Lax`, de 10 minutos y limitada a `/api/v1/auth/sso`; no se guarda en la base.
- Resolución de la cuenta: identidad SSO ya ligada (`users.sso_provider_id` + `sso_subject`, únicos); si no, usuario local con el mismo email solo si el proveedor dice `email_verified`; si no, alta automática si `auto_create_users` y el dominio está en `allowed_domains` (vacío = cualquiera), con handle derivado del email y sufijo numérico si choca. Usuarios desactivados nunca entran. Los errores regresan a `/login?sso_error=...`.
- Grupos: en cada entrada se sincronizan solo los grupos del `group_mapping` (valor del claim → grupo de Radicle): se agregan los que vienen en el claim y se quitan los mapeados que no vienen; los grupos no mapeados no se tocan.
- `password_login_enabled` vive en `instance_settings`. Apagado, solo el primer admin de instancia (el humano admin más antiguo) puede entrar con password; es la salida de emergencia documentada en el README.
- El client secret se guarda cifrado con `RADICLE_SECRET_KEY` y la API nunca lo devuelve.
- Los tests corren contra Keycloak 26 real en testcontainers (marca `slow`); el realm se configura por la API de admin con un mapper de grupos.
